# Suite entertainment art: source-first audit

Research only, 2026-10-29. No model, texture or PDF files were downloaded; no asset was generated, purchased, imported or rendered. Public metadata/license text and the operator PDF were inspected. This is an acquisition shortlist, not visual or runtime acceptance.

## Coverage and local reuse

The current normalized inventory contains **268 billiards variants and 267 media variants**. These are project inventory counts, not independently verified operator counts. `COVERAGE.json` retains every original unit ID. `GuestFloor._suite_fitout` currently puts the same sofa, small display, coffee table and bar in all variants; it does not supply pool tables or a distinct media-room fit-out.

49 local authored/provider GLBs were checked by filename, and the relevant original authoring code and GLB node/material metadata were inspected. No existing billiard table, balls or cues were found. Hawker tables are dining furniture, not substitutes. The local `interior_safe_furnishings.glb` is a merged safe-room scene; its editable `build_interiors.py:safe_room` already contains a contemporary sofa with separate arms and cushions, about 3.45 m overall width, plus a coffee table. Reuse that original geometry selectively if its actual suite render passes critique. Do not instantiate the whole safe-room model. `LOCAL_REUSE_AUDIT.json` records hashes and the existing whole-Blender-file rights caveat; a plain-material GLB is not proof that every saved source datablock is cleared.

## Correct source dimensions before placement

Root confirmed that the previous nine-foot size was **our reconstruction assumption, not the user's requirement**. Do not preserve it over better operator evidence.

I visually inspected the actual official [The Marina floor plan](https://www.marinabaysands.com/content/dam/marinabaysands/hotel/marina-suite/the-marina-floorplan.pdf), **page2**, in Chrome at500%. The right-hand room, above the circular dining area, labels the object **“POOL TABLE (8')”** and **“1500x2620”**. The separate media room on that page labels a98-inch smart TV. The table has inner pocket/bed and outer perimeter lines, but the annotation has no dimension arrows identifying which perimeter it measures. Reading2.620×1.500 m as the overall table footprint is therefore a reasonable **inference**, not a verified bed measurement or manufacturing drawing. The earlier search OCR text1800×900 was wrong and is explicitly rejected.

For a different current suite, the operator's [Sands Signature page](https://www.marinabaysands.com/hotel/rooms-suites/sands-signature-suite.html) lists140 m² average, pool/media/entertainment-den variants and an85-inch living-room television. It warns that actual layouts and furnishings vary. Keep suite type, source date and display role separate; do not universalize Marina's8-foot table or an85/98-inch display to every reconstructed suite.

If Root retains1.45 m cue clearance around a provisional2.62×1.50 m **outer** table, the resulting reservation is5.52×4.40 m. That clearance is a game design allowance, not a dimension verified from this operator PDF. A2.54×1.27 m playing bed can have a larger cabinet: the [3DAssets.dev nine-foot table page](https://3dassets.dev/assets/bowling-alley-and-pool-hall-pool-table-1e7397c5) lists a2.83×1.56 m whole model (publisher-reported AI-produced stock; not selected or acquired here). Never squash rails/pockets into bed dimensions to force a pass. Measure the chosen asset and revise the per-type placement reservation consistently.

## Integration gates

Acquire only the selected files through normal provider access. Preserve source URL, creator, version/hash, actual license/notices and modifications. Check metre scale, separate objects, UV/PBR maps, pockets and physical clearances, before building matching collision. Instance shared materials/meshes on streamed floors; do not load535 distinct full-resolution copies. Test representative close-up suite views and normal walking around the real table/sofa at production capsule size. The acceptance bar is actual quality and usable circulation, not a named object or a successful import.

No paid Customuse starts with53 credits, no Meshy, no API substitution. If a genuinely missing small accessory later needs generation, Root may use existing Tripo credits through browser control within the owner's routing. This audit authorizes no new generation. All candidates remain `NOT_ACQUIRED / NOT_RUNTIME_VERIFIED` at this checkpoint.
