# Render startup and final launch safety

Rules revision67f806 requires all GPU workloads to count, real headroom, a cold-launch cooldown and a machine-wide pause on a no-first-frame wedge. The installed shared coordinator now provides the main client/headroom/cooldown gate. This task adds the final owned-command checks and startup evidence below; it never edits or disables that coordinator.

- `render_gate.py` uses the normal held shared lease. It reads the installed workload inventory, supplements actual native Metal compute clients, simulators and hardware encoders, and checks every observed native Metal PID for E/Z regardless of its name. Different native GPU children remain distinct clients. A known UV launcher is removed only if a counted actual replacement exists. Command lines are not logged.
- The last check runs **after** the source/art snapshot, in the child PID that then execs the engine. Capacity cannot be assumed from a check made minutes before hashing. No launch occurs when headroom has disappeared, flags are active or a client is stuck. Rendered captures conservatively run alone until the recovery requirement is established.
- Current source helpers enable a first-frame protocol. The GameState hook starts only when explicitly requested, skips dummy-renderer headless mode, awaits a draw and completes a viewport image readback. A banner, spinner or submitted frame is not evidence. The marker must contain the current childPID and fresh supervisor nonce.
- The driver rejects caller-supplied/replayed health tokens before launch. Engine flags are parsed only before Godot's standalone `--`; a misplaced game argument named `--headless` cannot disable renderer shutdown protection.
- If the declared first-frame deadline expires, the driver creates the normal shared `PAUSED` switch without overwriting an existing pause, then sends TERM only to its owned child. It continues checking that deadline during the shutdown grace period. A possible renderer wedge never receives SIGKILL, even if the caller omitted health opt-in. There is no automatic resume.
- The current120second deadline is a **provisional declared2x60second expectation**. Metadata preserves that qualification; it is not a measured cold-start baseline. Real cold and warm observations must establish appropriate future thresholds.

The CPU regression suite uses synthetic protocol records and isolated pause directories, plus a real short-lived Python child to check orderly reaping. Its successful result proves protocol and control-flow behavior only. **No actual GPU frame/readback or GDScript native parsing has yet been verified for this new hook.** Those checks require the normal shared resource gate.

Older uninstrumented packages are not silently opted in. Rendered `bounded_run` calls without an explicit supported health protocol now refuse before engine launch. A fresh package must be exported from the instrumented source and its provenance verified before the package caller enables this protocol; adding a nonce to an old package would create a false wedge report. The current development source helper is instrumented; historic capture artifacts remain unchanged.
